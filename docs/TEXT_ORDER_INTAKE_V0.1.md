# 文字订单入口设计 V0.1

## 目标

支持员工直接提交聊天文字、截图或复制地址单，同时保持现有“公司识别 → 平台路由 → 商品映射 → 业务规则 → 管易Excel → 预检”链路不变。

## 模块边界

1. `Agent提取层`：读取文字或截图，按订单分段，生成带字段来源状态和不确定项的草稿。
2. `文字草稿门禁`：校验公司、渠道、订单身份、收件信息、商品、规格、数量、单位、联系方式和字段来源；仅输出脱敏预览与集中追问。预览同时说明“订单编号 > 来源单号 > 已登记自动生成规则”的实际编号路径。
3. `用户确认门禁`：普通核对延后到最终`preview_ready`Excel之后，与唯一商品候选在同一轮集中确认；关键缺失或歧义仍在准备阶段阻断。
4. `标准化输入层`：把草稿写为临时标准化Excel，并生成与文件SHA-256绑定的一次性自适应字段计划；临时商品映射另用规范化订单事实SHA-256绑定，避免同内容Excel重生成导致失效。
5. `现有转换总控`：继续负责公司路由、正式商品映射、套餐展开、店铺、单号、物流、备注、管易模板和上传前预检。

文字入口不维护第二套商品和物流规则。AI只负责从非结构化内容提出候选；可执行结论仍由脚本和版本化规则决定。

## 安全规则

- 原始文字或OCR全文不写入规则库、Skill、处理报告或聊天回复。
- 草稿和标准化Excel含收件信息，只保存在本次任务目录，并按订单源文件同等级保护。
- 对平台、订单号、联系方式、地址、商品或数量的推断必须标记为`inferred`并阻断。
- 用户确认文字识别结果不等于确认商品映射或业务规则；后续转换仍可继续追问。
- 收件信息只在最终预览中进行一次批次级脱敏核对；预览决策载荷直接携带`masked_order_preview`，Agent必须先交付完整预览Excel，再展示集中确认小节，不能先问后出表。普通聊天文字与截图/OCR都适用；已知固定模板Excel不进入该核对。
- 用户只确认候选正确但没有选择复用范围时，先按仅本次交付成品；成功结果用`mapping_reuse_bundle`非阻断询问是否以后沿用，不回复即保持仅本次。
- 没有公司级证据时必须询问公司。天猫、京东、淘宝等是渠道标签，不能单独决定公司规则。
- 来源单号缺失时不得随意生成。通用日期顺序号必须由用户确认具体参数并使用专用确认口令；已登记公司的固定生成规则由版本化来源配置执行。
- Agent先把自然语言拆成Schema字段；例如“橘色搓澡巾1条”应拆为商品名称“搓澡巾”、规格“橘色”、数量1、单位“条”，不能让模型直接选择管易代码。若名称和规格仍被合并，映射层只允许用当前正式映射中的名称+规格做精确正序/倒序组合拆分；唯一正式目标才自动命中，模糊或多候选仍追问。

## 当前范围

V0.1已实现草稿合同、脱敏校验、集中追问、用户确认门禁、标准化Excel与一次性计划生成。文字草稿可分别保留订单编号和来源单号，统一优先使用订单编号；两者均无时才调用来源已确认的分钟序号规则，并在确认预览中直接说明规则，不再反问用户是否补号。2026-10-15起所有新平台单号保留基础业务单号，不再追加机器人尾缀`A`。已登记公司或业务来源可以继续进入现有转换链路。商品字段采用“AI语义拆分到Schema + 确定性正式映射校验”：正式名称+规格被Agent合并为一个短语且规格为空时，可按已发布映射做唯一精确组合拆分；这不是模糊匹配。尚舆自营天猫/京东文字玉米单按渠道分配旗舰店；自营“袋”匹配8棒家庭装，“根”尚未登记时追问；自营“京东中通”表示京东旗舰店订单且物流字段原样填写`京东中通`。淘橘子淘宝/KQYD日用品文字单在缺少两类订单标识时分别使用`TB`/`KQYD`分钟弹性序号，未指定物流默认韵达。RZD同样只在两类订单标识均缺失时生成分钟单号。JZDZ/DRJY作为员工可见的独立手工来源，缺号时分别生成`JZDZ`/`DRJY`+`YYMMDDHHmm`+弹性序号，商品映射后再由正式SKU—店铺关系选择店铺。裸棒在普通发货中禁用。

2026-10-13新增混合手工订单入口：Agent确认输入属于非Excel订单且用户没有指定公司或规则包时，默认进入`registered_manual_channels`模式。入口逐单用已登记的渠道标记选择来源配置，按公司与规则包分组，分别执行原有确定性规则并返回结构化`conversion_inputs`，最终仍由统一批次入口默认合并成一个管易Excel。路由层不复制店铺、会员、单号、商品或物流规则。唯一命中时不增加“是否手工订单”的确认；现有脱敏预览确认同时确认提取和路由结果。未知或多重命中的单笔只追问来源。用户已指定公司或规则包时继续走单一来源模式。
