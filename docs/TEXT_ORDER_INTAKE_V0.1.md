# 文字订单入口设计 V0.1

## 目标

支持员工直接提交聊天文字、截图或复制地址单，同时保持现有“公司识别 → 平台路由 → 商品映射 → 业务规则 → 管易Excel → 预检”链路不变。

## 模块边界

1. `Agent提取层`：读取文字或截图，按订单分段，生成带字段来源状态和不确定项的草稿。
2. `文字草稿门禁`：校验公司、渠道、来源单号、收件信息、商品、数量、联系方式和字段来源；仅输出脱敏预览与集中追问。
3. `用户确认门禁`：只有用户确认脱敏预览后，草稿才允许生成转换输入。
4. `标准化输入层`：把确认草稿写为临时标准化Excel，并生成与文件SHA-256绑定的一次性自适应字段计划。
5. `现有转换总控`：继续负责公司路由、正式商品映射、套餐展开、店铺、单号、物流、备注、管易模板和上传前预检。

文字入口不维护第二套商品和物流规则。AI只负责从非结构化内容提出候选；可执行结论仍由脚本和版本化规则决定。

## 安全规则

- 原始文字或OCR全文不写入规则库、Skill、处理报告或聊天回复。
- 草稿和标准化Excel含收件信息，只保存在本次任务目录，并按订单源文件同等级保护。
- 对平台、订单号、联系方式、地址、商品或数量的推断必须标记为`inferred`并阻断。
- 用户确认文字识别结果不等于确认商品映射或业务规则；后续转换仍可继续追问。
- 没有公司级证据时必须询问公司。天猫、京东、淘宝等是渠道标签，不能单独决定公司规则。
- 来源单号缺失时不得随意生成。通用日期顺序号必须由用户确认具体参数并使用专用确认口令；已登记公司的固定生成规则由版本化来源配置执行。

## 当前范围

V0.1已实现草稿合同、脱敏校验、集中追问、用户确认门禁、标准化Excel与一次性计划生成。已登记公司可以继续进入现有转换链路。尚舆自营天猫/京东文字玉米单按渠道分配旗舰店、复制来源平台单号并由公共层追加`A`；自营“袋”匹配8棒家庭装，“根”尚未登记时追问；自营“京东中通”表示京东旗舰店订单且物流字段原样填写`京东中通`。淘橘子淘宝/KQYD日用品文字单按渠道拆分为两个来源再合并输出，店铺均为淘橘子，基础单号分别用`TB`/`KQYD`+生成分钟+弹性序号，未指定物流默认韵达。RZD“根”匹配彩袋单棒装并按根数写数量。裸棒在普通发货中禁用。只有平台词而没有公司证据时仍先向用户确认。长期确认的新包装含义保存到本机待登记库；长期商品映射进入飞书待确认表，由所有者发布器审核后进入正式库。
